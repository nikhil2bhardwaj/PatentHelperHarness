01Overview

Patent Helper Harness is an AI-powered, multi-phase ideation pipeline designed for automotive R&D patent discovery. It chains 13 LLM-driven phases — from initial user intent capture through research, idea generation, prior-art analysis, feasibility, risk review, and final patent disclosure drafting — with human-in-the-loop gates between each phase.

The system supports enterprise LLM providers (OpenAI Anthropic Gemini OpenAI-Compatible), a zero-cost mock mode for offline testing, and both a modern web UI (React + Tailwind + FastAPI) and a rich CLI interface.

Key Capabilities

  • 13-phase sequential pipeline with LLM-generated JSON output at each phase
  • Human-in-the-loop gates: Accept & Advance, Refine (Edit), Feedback, Rerun, Cumulative view, Save & Exit
  • Autonomous mode: Auto-accept and chain all phases without manual review
  • Save & Resume: Sessions auto-save after every gate action; resume from any saved session checkpoint
  • Phase output referencing: Select completed phase outputs to inject as additional context into the next phase run
  • Dual-Tier Export: Download individual phase outputs (.md, .pdf, .docx) and the complete cumulative session patent dossier (.pdf, .docx, .md)
  • Output compression: Token-aware truncation to fit context windows when passing outputs between phases (60–80% token reduction)
  • Multi-provider support: OpenAI (GPT-4o), Anthropic (Claude 3.5), Google Gemini (1.5 Pro), custom OpenAI-Compatible endpoints (Ollama, vLLM, DeepSeek, Groq), or Mock (no API key needed)

High-Level Flow

  1. User provides an initial input (or leaves empty for Autonomous mode)
  2. For each phase (0–12), the system loads a prompt template from Innovation Prompts/
  3. Template variables ({{USER_INPUT}}, {{PHASE_N_OUTPUT}}, etc.) are substituted with real values
  4. The assembled prompt + system prompt are sent to the LLM via the selected provider
  5. The LLM returns structured JSON output
  6. Output is saved to disk and displayed to the user
  7. The user reviews via a gate: Accept, Edit, Feedback, Rerun, or Save & Exit
  8. On accept, the output becomes input context for the next phase (compressed if needed)

Two Interfaces

Web App (FastAPI + React)

  • Backend: web/backend/main.py — FastAPI server with REST endpoints
  • Frontend: web/frontend/ — React + TailwindCSS SPA
  • Runs on http://127.0.0.1:8000
  • Full UI with sidebar, gate panel, modals, export buttons

CLI (run_harness.py)

  • Terminal-based interactive workflow
  • Rich-formatted console output
  • Gate options via numbered menu (1–6)
  • Supports --resume, --mock, --provider flags

0413-Phase Pipeline

Each phase has a dedicated prompt template in Innovation Prompts/. The system runs them sequentially, passing the output of each phase as compressed context to the next.

12

Inter-Phase Context Flow

  • Phase 0: Receives {{USER_INPUT}} — the user's initial idea description
  • Phases 1–10: Each receives {{PHASE_N-1_OUTPUT}} — the compressed output of the previous phase
  • Phase 11: Receives {{HISTORICAL_CONTEXT}} — aggregated outputs from phases 5–9 (fact-checking against earlier analysis)
  • Phase 12: Receives {{CUMULATIVE_CONTEXT}} — aggregated outputs from phases 4–10 (final synthesis)
  • User-referenced phases: The user can select any completed phase outputs to inject as additional [REFERENCED OUTPUT] blocks into the prompt
  • Feedback: User-provided feedback for a phase is prepended to the next phase's prompt as [ADDITIONAL USER FEEDBACK]

Output Compression

When COMPRESS_PHASE_OUTPUTS = True (default), outputs exceeding OUTPUT_COMPRESSION_THRESHOLD (6000 tokens) are truncated using tiktoken before being passed to the next phase. This prevents context window overflow on long sessions.

05Backend API (FastAPI)

The backend is a FastAPI application in web/backend/main.py. It maintains in-memory session state and persists outputs to disk.

REST Endpoints

MethodPathDescription

POST/api/sessions/{id}/gateSubmit gate decision (accept, edit, feedback, exit, rerun)
GET/api/sessions/{id}Get session metadata (current phase, completed phases, model)
GET/api/sessions/{id}/cumulativeGet cumulative output across all phases
GET/api/sessions/{id}/phase/{phase}Get a specific phase's output
GET/api/sessions/{id}/phase/{phase}/exportExport phase output in Document View as ?format=md|pdf|docx
GET/api/sessions/{id}/cumulative/exportExport full cumulative dossier in Document View as ?format=md|pdf|docx
GET/api/sessions/listList all saved sessions from outputs/
POST/api/sessions/resumeResume a saved session (accepts session_dir path)

Session Lifecycle

1. POST /api/sessions           → Creates in-memory session, returns session_id
2. POST /api/sessions/{id}/run/{phase}  → Calls LLM, returns output, status = awaiting_gate
3. POST /api/sessions/{id}/gate         → User decision (accept/edit/feedback/exit/rerun)
   ├── accept  → saves output, advances to next phase
   ├── edit    → saves edited output, advances to next phase
   ├── feedback → saves feedback for next phase, advances
   ├── exit    → saves state, session paused
   └── rerun   → re-runs current phase
4. Auto-save after every gate action (except rerun)
5. GET /api/sessions/list    → Lists all saved sessions
6. POST /api/sessions/resume → Reloads session from disk into memory

Document View Export Endpoints

Both Phase (/phase/{phase}/export) and Cumulative Dossier (/cumulative/export) export endpoints generate publication-quality Document View deliverables instead of raw JSON syntax:

  • .md: Formatted Markdown with executive summaries, blockquoted patent claims, prior art matrices, and clean bullet lists (no raw JSON braces or brackets)
  • .pdf: Publication-ready PDF generated directly from Document View layout with formal hierarchy and page margins
  • .docx: Microsoft Word document generated using native headings, bullet lists, and quote block styles

07Features

Save & Resume

  • Sessions are auto-saved to outputs/session_YYYYMMDD_HHMMSS/ after every gate action (accept, edit, feedback, exit)
  • session_state.json stores: current phase, completed phases, user input, model, provider
  • All phase outputs are saved as individual .md files
  • "Resume Saved Session" button on start screen lists all sessions with metadata
  • Resume reloads all completed outputs into memory and positions at the next uncompleted phase

Phase Output Referencing

  • On the idle screen (before running a phase), a "Reference Completed Phases" button appears if completed phases exist
  • Clicking opens a panel with checkboxes for each completed phase
  • Selected phase outputs are compressed and prepended to the prompt as [REFERENCED OUTPUT] blocks
  • Multiple phases can be selected simultaneously
  • Badge count shows how many phases are currently selected

Export (MD / PDF / DOCX)

Phase Deliverable Export

  • Three export buttons (.md, .pdf, .docx) appear in the top workspace header for the current active or viewed phase
  • Works in both "viewing completed phase" and "awaiting gate" modes
  • .md: Structured Markdown with headings, bullet lists, and key-value attributes
  • .pdf: Formatted multi-page PDF with heading hierarchy and clean typography (via fpdf2)
  • .docx: Word document with native heading styles and formatted lists (via python-docx)

Full Cumulative Session Dossier Export

  • Export the complete multi-phase compiled patent disclosure dossier at any point:
  • Direct header buttons: Dossier: [.pdf] [.docx] [.md]
  • Cumulative modal header: Export Dossier: [.pdf] [.docx] [.md]
  • Builds the compiled document across all completed phases with section headers, index mappings, claims, and strategic analyses in a single unified deliverable
  • Endpoint: GET /api/sessions/{session_id}/cumulative/export?format={md|pdf|docx}

Autonomous Mode

  • Selectable from the start screen
  • Auto-accepts each phase output and chains to the next without manual review
  • "Stop Auto-Run" button available during execution
  • Still saves state after each auto-accept

Output Compression

  • Enabled by default (COMPRESS_PHASE_OUTPUTS = True)
  • Outputs exceeding OUTPUT_COMPRESSION_THRESHOLD (6000 tokens) are truncated via tiktoken
  • Phase 11 receives historical context from phases 5–9 (compressed)
  • Phase 12 receives cumulative context from phases 4–10 (compressed)
  • Token warning threshold at 50,000 tokens for aggregated contexts

Gate System

Prompt Templates

Prompts are stored as plain text files in Innovation Prompts/. Each prompt contains {{VARIABLES}} placeholders that are substituted at runtime. When USE_JSON_OUTPUT = True, the prompt loader automatically transforms the <output_instructions> section to request JSON-formatted responses.

09Starting & Stopping the Server

Prerequisites

  1. Python 3.10+ installed
  2. Node.js 18+ (bundled in node-v26.5.0-win-x64/ for Windows)
  3. .env file with at least one provider's API key

First-Time Setup

# 1. Install Python dependencies
pip install -r requirements.txt

# 2. Create .env from example
copy .env.example .env
# Edit .env and add your API keys

# 3. Build the frontend (one-time, or after UI changes)
cd web/frontend
npm install
npm run build
cd ../..
Note: On this Windows machine, Node.js is bundled at node-v26.5.0-win-x64/. If npm is not on your PATH, use the full path: 
node node-v26.5.0-win-x64\node_modules\npm\bin\npm-cli.js run build --prefix web/frontend

Start the Web Server

python -m uvicorn web.backend.main:app --host 127.0.0.1 --port 8000

Then open http://127.0.0.1:8000 in your browser.

What happens on start:
  • FastAPI loads .env via python-dotenv
  • Prompt templates are loaded from Innovation Prompts/
  • Static frontend files are served from web/frontend/dist/
  • Sessions are stored in memory (not persisted across server restarts, but outputs on disk survive)

Stop the Web Server

Method 1: Keyboard Shortcut (Recommended)

Press Ctrl + C in the terminal where the server is running. This gracefully shuts down uvicorn.

Method 2: Find and Kill Process (Windows)

# Find the process ID (PID) listening on port 8000
netstat -ano | findstr :8000

# Kill the process (replace PID with the number from above)
taskkill /PID <PID> /F

Method 3: Kill by Process Name (Windows)

taskkill /F /IM python.exe /FI "WINDOWTITLE eq *uvicorn*"
Important: In-memory session state is lost when the server stops. However, all phase outputs and session state files on disk remain. Use "Resume Saved Session" after restarting to continue a previous session.

Rebuilding the Frontend

After making changes to files in web/frontend/src/, rebuild the frontend:

# Standard (if npm is on PATH)
cd web/frontend && npm run build

# On this machine (using bundled Node.js)
node node-v26.5.0-win-x64\node_modules\npm\bin\npm-cli.js run build --prefix web/frontend

The built files go to web/frontend/dist/ and are served automatically by FastAPI on next page load.

10CLI Mode

The CLI mode (run_harness.py) provides the same 13-phase pipeline in a terminal interface using rich for formatted output.

Basic Usage

# Interactive mode (prompts for user input)
python run_harness.py

# With initial input
python run_harness.py --input "Battery thermal management for EVs"

# With specific provider
python run_harness.py --provider groq
python run_harness.py --provider openai
python run_harness.py --provider nararouter

# Mock mode (no API key needed)
python run_harness.py --mock

# Resume a saved session
python run_harness.py --resume outputs/session_20240101_120000/

# Override model and temperature
python run_harness.py --model gpt-4o --temperature 0.5 --max-tokens 8192
